A sample is made of phases now, and a phase is what it is made of AND the structure that indexes it — edited in one popout. Those used to be apart: the dock held a flat element list, the orientation wizards held .cif paths, and the COD search silently read the first to fill the second, which could not describe a two-phase sample at all. The query asks for a structure containing EXACTLY the elements given, so a Cu/Nb sample searched as one composition asks for a Cu-Nb compound and gets nothing back, while fcc Cu and bcc Nb are one query each; Zr/Nb is worse than empty, returning the solid solution that is neither phase in the alloy. "＋ Elements and Phase" opens the periodic table, where ``＋ Phase`` adds a selectable phase and clicking elements builds whichever phase is selected — so a phase is a SUBSET of the composition, and an element can belong to the sample without belonging to any phase (the extra oxygen in neither structure you are indexing against). Each phase loads a .cif or searches COD scoped to its own elements, taking its elements from the file when it has none; the dock lists the phases with their structures, and both orientation wizards' Load tabs read that same list instead of a private one, so a structure chosen anywhere is recorded on the dataset and survives closing the caret. ``Sample.elements`` and ``Sample.composition`` are unchanged — still the flat union that EELS edge suggestion and EDS quantification read.
